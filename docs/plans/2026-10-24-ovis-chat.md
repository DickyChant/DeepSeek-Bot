# Ovis direct conversation bridge (personal fork)

The botBridge Cordis service exposes selected own-chat history, queued text sends,
and filtered live events. It reuses DS Bot parts and the existing feed; it never
creates a second runtime or patches Harness. Persistent runtime/Bot IDs select the
recipient, not an arbitrary Session ID. History crosses rotations through the
existing cursor; group chats, attachments, cards and approval controls remain in DSH.

The optional Herdr plugin authenticates its local HTTP routes using a private
server-to-server credential. Ovis retains its browser authentication, origin and
watch-device restrictions. No DSH browser cookie is forwarded. The directory stays
metadata-only and backward compatible.

Sends retain their request ID and outcome in a bounded in-process cache. DSH receives
the same request ID. Failed or uncertain sends are not replayed. This is not a
persistent exactly-once ledger across host restarts. Ovis preserves the draft and
requires the user to check the history before deciding to send again.

Streams are ephemeral, bounded connections. Reconnect reloads authoritative chat
history; text deltas are not replayed by event ID. This avoids claiming lossless
partial-text replay across restarts. Only the selected Bot own-chat events cross
the service; hidden delegation replies retain DS Bot feed filtering.
